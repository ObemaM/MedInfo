# 2026-05-01: Открытие правильного вызова из SignalR

## Кратко

Исправлена ошибка, из-за которой новый SignalR-вызов мог открыть экран принятия решения, но на экране показывался первый старый вызов из локальной очереди.

## Изменения

- `SignalRService` теперь передает `HospitalizationResponseDto` в `IncomingCallActivity` через `EXTRA_HOSPITALIZATION`.
- Экран принятия решения после fullscreen-открытия должен показывать именно новый вызов, пришедший из SignalR.
- Операции `CallsManager` синхронизированы, чтобы серверная загрузка списка и SignalR не могли одновременно создать дубли таймеров для одной госпитализации.

## Проверка

- `java -jar .\gradle\wrapper\gradle-wrapper.jar :app:assembleDebug` - успешно.
- `java -jar .\gradle\wrapper\gradle-wrapper.jar :app:lintDebug` - успешно.

## Заметки

- По логам было видно, что после новых госпитализаций `f2f9...`, `a059...`, `6b6...` экран каждый раз показывал старую госпитализацию `c9c63...`. Это происходило потому, что intent открывал экран без данных конкретного нового вызова.
- В логах также был двойной `timer-started` для `c9c63...`: это похоже на гонку между серверной синхронизацией списка и SignalR.
- Отдельно нужно уточнить timezone серверных дат: в логах серверные `notificationTime` выглядят примерно на 2 часа вперед относительно logcat, поэтому оставшееся время может выглядеть неожиданно, если сервер присылает дату без timezone offset.
