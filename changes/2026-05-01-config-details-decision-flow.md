# 2026-05-01: Конфиг, детали вызова и очередь решений

## Кратко

Подготовлен первый рабочий контур для новой логики информатора: локальный экран настроек, подробный просмотр вызова, вкладка "Требуют решения" с таймером, экран принятия/отклонения без нижней очереди и без поля сообщения бригаде.

## Изменения

- Добавлен локальный вход `admin / 0000`, который открывает экран настроек без создания серверной сессии.
- Добавлен экран редактирования конфига: адрес сервера, таймауты, таймер принятия решения, задержка тестового вызова и отключение SignalR для тестов.
- Конфиг теперь загружается из внутреннего `config.json`, а стартовые значения берутся из `assets/config.json`.
- Зафиксирована портретная ориентация основных экранов приложения.
- Добавлен экран подробной информации по госпитализации: активные и архивные вызовы открывают все непустые поля из нового DTO.
- В активных деталях оставлен placeholder под будущий чат; в архиве placeholder скрывается.
- Вкладка "Требуют решения" открывает экран принятия решения, а активные и архивные вызовы открывают детали.
- Карточки во вкладке "Требуют решения" показывают оставшееся время и сортируются по минимальному времени до истечения решения.
- Таймеры карточек пересчитываются локально раз в секунду, без повторного открытия вызова.
- Экран принятия решения упрощен: убрана нижняя очередь вызовов, убрано поле "Сообщение для бригады", добавлен placeholder "Чат".
- При принятии/отклонении теперь отправляется только решение по госпитализации; сообщения будут жить в отдельном чате.
- Исправлена неточность: если в локальной очереди несколько вызовов, экран решения сохраняет выбранный вызов, а не переключается на первый элемент очереди.
- Удалены неиспользуемые остатки старой нижней очереди: `SideTabsAdapter`, `item_side_tab.xml`, зависимость `flexbox`.
- SignalR учитывает новое поле `IsNotificationSent` и подтверждает прием по правилам из серверной документации.
- Для сообщений от планшета локально фиксируется старт таймера принятия решения.
- Тестовый exact alarm теперь проверяет доступность точных будильников и корректно откатывается на обычный alarm, если разрешения нет.
- В измененных участках кода добавлены русские комментарии к неочевидной логике.

## Заметки

- Реальный серверный вход, живой SignalR и полный путь "пришел вызов -> принято решение" не проверялись интерактивно, потому что в текущем окружении нет серверных учетных данных и тестового серверного события.
- Прямой запуск `MainActivity` через `adb am start` невозможен, потому что activity не экспортирована; это нормально для приложения, но ограничивает ручной обход без авторизации.
- Следующий логичный шаг: добавить на экран решения счетчик оставшихся вызовов, требующих решения, и затем начать проектировать полноценный чат по `hospitalizationId`.

## С чего начать в следующий раз

- Проверить сценарий с реальным сервером: вход обычным пользователем, загрузка вкладок "Требуют решения", "Активные", "Архив".
- Проверить живой SignalR: приходит ли `HospitalizationNotification`, добавляется ли вызов в очередь, подтверждается ли получение через `/hospitalizations/confirm-reception`.
- Проверить сценарий сообщения от бригады: приходит ли `MessageNotification` с `Origin = 1`, стартует ли локальный таймер решения, подтверждается ли уведомление только когда `IsNotificationSent = false`.
- Проверить принятие и отказ решения из вкладки "Требуют решения": уходит ли `/hospitalizations/save-decision`, исчезает ли вызов из списка после обновления, не появляется ли он снова.
- Проверить, что сортировка по оставшемуся времени совпадает с ожиданием врача: чем меньше времени осталось, тем выше карточка.
- Добавить на экран принятия решения счетчик оставшихся вызовов, например "Требуют решения: N", и решить, должна ли эта плашка мигать/подсвечиваться при новом вызове.
- Решить UX для уведомления о новом вызове, когда врач уже смотрит другой вызов: не перебивать текущий экран, а подсвечивать счетчик или показывать краткий верхний баннер.
- Начать проектирование чата: базовый вариант - чат привязан к `hospitalizationId`; расширенный вариант - отдельный список чатов по активным вызовам с бейджами новых сообщений.
- Проверить сохранение конфига после перезапуска приложения: меняется ли серверный адрес, не ломается ли `RetrofitClient`, правильно ли пересчитывается SignalR URL.
